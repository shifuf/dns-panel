## 本次真实执行发现并修复的问题

1. 七牛旧部署记录把证书名 `*.shifuf.com` 当作实际 CDN 目标。通过 API 与 TLS 验证原绑定后修正为 qn.shifuf.com，并登记又拍云原有实际绑定，让后台续期钩子能跟踪它们。
2. EdgeOne 自动续期只从面板登记的加速记录找目标，漏掉原生云端域名。现在分页发现已启用 HTTPS 的原生目标，保留有效 EdgeOne 凭证/站点身份并按账号去重。
3. 全量加速同步可能用较早到期的单域名证书覆盖刚续期的通配符证书。现在对已成功且有效的较新绑定执行防降级检查，跳过结果不计作新部署。
4. 腾讯上传响应读错字段 `CertId`，实际上传成功却报没有证书 ID。现在解析 `CertificateId`，兼容历史字段与 `RepeatCertId`。
5. 腾讯详情没有输出指纹，导致上传复用失效。从公开 PEM 提取真实 UTC 时间和 SHA-256 后，能够复用已上传的新证书，不返回私钥。首次失败阶段产生的三份额外云端副本，在核对本次指纹、别名和已使用 ID 后已清理；保留正在使用的 cMkzYqdz。
6. 又拍云更换已有证书不能直接再次绑定，否则报 21713。现在识别真正 https=true 的生效项、校验旧证书只绑定当前目标后迁移，保留原 HTTPS 设置；多域名整体迁移不会被单域名调用擅自触发。
7. 又拍上传响应缺少可解析 ID 时，上层列表兜底与绑定查询紧邻，触发 RepeatCallInterface/21000。现在同客户端、同域名的成功列表短缓存 2 秒，任何写入都会清空缓存，换证后重新读取新状态。
